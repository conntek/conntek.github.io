# 博客文章统一排版规范

适用于 `content/blog/<slug>.json`。这些文章原本发在微信公众号上，排版五花八门；搬到官网后**统一是第一要务**：16 篇读起来必须像同一个编辑部出的。

**总原则：只改排版，不改内容。** 技术论述、数字、结论、产品主张一律照原文保留，不增加原文没有的事实，不删减原文的技术内容。可以修正错别字和明显的标点错误。

## 1. 输出字段

在原 JSON 上补/改这些字段（其余字段不动）：

| 字段 | 要求 |
|---|---|
| `body_raw` | 把原来的 `body` 原样搬到这里留档（只在第一次处理时搬，已存在就不要覆盖） |
| `category` | 四选一：`新品发布` / `产品解读` / `应用方案` / `技术科普` |
| `lead` | 导语，一段话 60~100 字，概括全文讲什么。用原文开头或原文里的句子压缩而成，不加原文没有的信息 |
| `takeaways` | 「本文要点」，3 条，每条 ≤ 40 字，从正文里提炼，必须能在正文里找到依据 |
| `cover` | 保留原字段不动 |
| `hero` | 正文里最能代表主题的一张内容图路径（如 `/blog/<slug>/5.webp`）；没有合适的写 `null` |
| `body` | 按下面第 2 节规范重排后的 Markdown |
| `removed` | 数组，逐条写清删掉了什么（例如「结尾公司简介段」「第 7、9、11、13 张为序号装饰图」「二维码图」），供人工复核 |

## 2. 正文 body 规范

### 结构
- 不写一级标题（页面模板会放标题），不重复写导语。
- 正文按 **2~5 个 `## ` 小节**组织。小节标题取原文的小标题，去掉装饰符号（`******`、`▍`、`01`、emoji 等），压到 **4~14 个字**的名词短语。
- 原文没有小标题的，按原文段落的话题分节，小节标题用中性描述（如「工作原理」「应用场景」「方案优势」），不许写成观点句或营销口号。
- 小节下的并列要点（原文里的「1. xxx」「一、xxx」、加粗行、配了序号图标的段落）统一用 `### ` 三级标题，**不带序号**，4~16 字。
- 不许出现四级及以下标题。

### 段落与强调
- 段落之间空一行；删掉段首全角空格缩进。
- **正文不使用加粗和斜体**（原文的加粗全部去掉；伪标题改成标题）。
- 不使用 emoji、装饰符号、分隔线（`---`、`END`、`———`）。

### 列表
- 无序列表用 `- `，有序列表用 `1. `，列表项内不加粗、不以句号以外的装饰开头。

### 图片
- **保留内容图**：原理图、框图、波形/曲线、实测数据图、产品照片、应用场景照片、参数表截图。
- **删除装饰图**：顶部/底部横幅、标题栏图片、序号徽章/小图标、分隔花边、二维码、公众号名片、logo 条、「点击下载 datasheet」之类的引导图、与正文无关的氛围图。判断不了时**打开图片看一眼**（用 Read 工具读 `docs/public/blog/<slug>/N.webp`），不要凭位置猜。
- 图片独占一行，格式：`![图注](/blog/<slug>/N.webp)`。图注 6~24 个字，优先用原文图下方的说明文字（并把原文那行说明删掉，避免重复）；原文没有说明的，按图片内容写一个中性描述（如「KTH78 系列典型应用框图」「多对极磁环校准前后误差曲线」），不写评价。
- 不改图片路径与文件名。

### 表格
- 真实数据表用 Markdown 表格，表头一行，单位写进表头。
- 原文拿表格做排版容器的（只有一格、放联系方式等），删掉。

### 文字规范
- 中文与英文/数字之间加一个半角空格：`KTH78 系列`、`0.1 度` → 见下条单位。
- 数字与单位之间加空格：`10 μs`、`1000 rpm`、`-40 ~ 125 ℃`、`16 bit`、`5 V`。角度用 `°`：`0.1°`（`°` 与数字之间不加空格）。
- 范围一律 `~`，两侧加空格。
- 转速单位统一小写 `rpm`；微秒统一 `μs`（希腊字母 μ，不用 u 或 µ）；温度 `℃`。
- 中文语境用全角标点（，。；：？！「」），英文型号与数字内部保持半角。
- 型号大小写照原文与官网写法（`KTH7801`、`KTH78 系列`），不要在正文里手工加链接（渲染时会自动加）。

## 3. 统一删掉的公众号尾巴
- 「END」、往期推荐、关注/扫码/点赞/在看引导、公众号名片与二维码
- 结尾的公司简介段（「昆泰芯微电子科技有限公司是一家……」）
- 联系方式与样品申请段（官网页面底部统一有联系入口）
- 「点击上图下载 datasheet」「阅读原文」之类的引导语
- 视频占位（`（此处为视频，请在原文中观看：…）`）**保留**，改写成一行：`> 本文含视频，请在原文中观看。`

以上删除项都要记进 `removed`。

## 4. 自检清单（交付前逐条过）
- [ ] `## ` 小节 2~5 个，标题 4~14 字；`### ` 不带序号
- [ ] 全文无 `**`、无 emoji、无 `END`、无公司简介和联系方式
- [ ] 每张保留的图都有图注；删掉的图都在 `removed` 里
- [ ] 数字、结论与 `body_raw` 对照无增删
- [ ] 中英文空格、单位空格、`rpm`/`μs`/`℃`/`°` 统一
- [ ] `lead` 60~100 字，`takeaways` 3 条各 ≤ 40 字，`category` 在四个选项内
- [ ] JSON 用 Python `json.dump(ensure_ascii=False, indent=1)` 写回并读回确认合法（不要用 bash heredoc 写文件）
