## P0（数据错）

### P0-1 四个页面的 H1 不是一个型号，一页顶了 9 个订购型号

`型号` 单元格里塞了多个料号，`render_model_pages` 直接把整格当 `mid` 用。

| 页面 | H1 实际渲染 | 源 |
|---|---|---|
| `docs/products/switch/linear-hall/kth5641a1-kth5641a2-kth5641a3-kth5641a4.md` | `# KTH5641A1`，后面 `KTH5641A2 KTH5641A3 KTH5641A4` 掉成了正文段落 | specs.json `linear-hall` 行 1，`型号` = `"KTH5641A1\nKTH5641A2\nKTH5641A3\nKTH5641A4"` |
| `docs/products/switch/linear-hall/kth5642a1-kth5642a2.md` | 同上，2 个 | 行 3 |
| `docs/products/switch/linear-hall/kth5643a1-kth5643a2-kth5643a3-kth5643a4.md` | 同上，4 个 | 行 4 |
| `docs/products/switch/ktm28/ktm2801-ktm2802.md` | `# KTM2801 / KTM2802` | specs.json `ktm28`，`型号` = `"KTM2801 / KTM2802"` |

连带三处坏掉：

1. **frontmatter YAML 被换行撑破**：`title: "KTH5641A1\nKTH5641A2\nKTH5641A3\nKTH5641A4 · KTH564 系列线性霍尔芯片"`——双引号标量里的 `\n` 会被 YAML 解析成真换行，`<title>` 变成多行。
2. **面包屑 `<span>` 里也是裸换行**。
3. **一页同时代表 4 个不同规格的料号**：该页关键参数芯片 `灵敏度` 显示 `A1: 1.5 mV / A2: 2.0 mV / A3: 2.5 mV / A4: 3.0 mV`，`磁场范围` 同理 `±1600 / ±1200 / ±960 / ±800 Gs`——读者拿不到「KTH5641A2 到底多少」。已截图确认（`.../conntek-qa3/shots/products_switch_linear-hall_*.png`）。

**建议改法**（`render_model_pages`，行 740 起）：在遍历 `matrix['rows']` 之前先做一次「行展开」——把 `row[0]` 按 `\n` 与 ` / ` 切成 N 个料号，每个料号生成一行；同一行里形如 `A1: 1.5 mV\nA2: 2.0 mV` 的取值按 `^(后缀)\s*[:：]` 解析后各取自己那一条，解析不出来的保持整格。ktm28 那行把 `KTM2801 / KTM2802` 拆成两页即可（两者参数相同）。

### P0-2 9 个 KTH78 页把占位符 `/` 当成参数值显示

`极限加减速延时` 一栏显示为 `/`：
`kth7812-x-n-qn16` `kth7813-x-n-qn16` `kth7816-x-n-qn16` `kth7816-x-n-sop8` `kth7816-x-c-sop8` `kth7823-x-n-qn16` `kth7823-x-c-qn16` `kth7823-x-c-sop8` `kth7824-x-n-qn16`。

来源是 figures.json 的「KTH78 系列型号选型表」，该图里这一格写的是 `/`（表示无此项）；而 specs.json 同一型号这一格是 `—`。`merged_matrix` 只把 `""` 和 `"—"` 当空（行 441、462），`/` 被当成有效值填了进去，还盖过了「系列参数对比」里同型号的真值。

**建议改法**：把空值判据抽成一个常量并扩集——`EMPTY = ('', '—', '-', '/', '／', 'N/A', 'NA', '—', 'NC')`，`merged_matrix` 里两处 `v in ("", "—")`、`render_model_pages` 里 `str(v).strip() not in ('', '—')`、`transposed_table` 一并改用它。（`NC` 目前只影响 `kth7101-sop8` 的 `PWM 频率`，同一处改掉。）

### P0-3 两份仓库内源表对同一型号的关键数字打架，页面只显示其中一份且不作任何提示

`merged_matrix` 把差异收进 `conflicts`，但 `conflicts` 只在系列页用（`merged_spec`），**型号页完全不呈现**。差异集中在 KTH78，8 个页面的头条数字受影响：

| 页面 | 字段 | 页面显示（型号选型表） | 另一源（系列参数对比） |
|---|---|---|---|
| `kth7801-x-{n,c}-{qn16,sop8}`（4 页） | 工作温度 | `-40 ~ 150 ℃` | `-40 ~ 125 ℃` |
| `kth7813-x-n-qn16` | 噪声（1σ） | `0.004°` | `0.015°` |
| `kth7813-x-n-qn16` | 工作磁场 | `30 ~ 150 mT` | `15 ~ 150 mT` |
| `kth7815-x-n-qn16` / `-sop8` | 噪声（1σ） | `0.059°` | `0.24°`（相差 4 倍，且 `噪声` 进了关键参数芯片） |
| `kth7815-x-n-qn16` / `-sop8` | 工作磁场 | `30 ~ 150 mT` | `15 ~ 150 mT` |
| `kth7824-x-n-qn16` | 噪声（1σ） | `0.004°` | `0.007°` |
| `kth7824-x-n-qn16` | 工作磁场 | `30 ~ 150 mT` | `40 ~ 150 mT` |

（同一比对里 `供电电压 3.0~5.5 V vs 3.3 V/5 V`、`CRC 否/是 vs 可选`、`输出接口 PWM/SPI vs SPI/SSI/PWM/ABZ` 共 35 处**不算错**——「系列参数对比」是按基础型号写的粗粒度表，封装变体的差异本来就该以订购型号表为准。上表挑出的是**同一基础型号内两份都该一致却不一致**的项。）

**建议改法**：`render_model_pages` 里把该型号命中的 `matrix['conflicts']` 取出来，渲染成 `参数详情` 下方的一行 `<p class="c-note">`（「本参数两份资料记载不一致：X / Y，以产品手册为准」）；同时这 8 条要回头找 datasheet 定谁对，不该由渲染器默默择一。

## P1（缺失 / 匹配错）

### P1-1 89 个页面同一参数显示两遍，取值写法还不一样

`label_key()`（行 399）先把空格、括号内容剥掉做同义词查表，**但查不到时返回的是原始列名**，于是归一化后同键的两个列名各活各的：

| 页面数 | 重复字段 | 实例 |
|---|---|---|
| 81（kth16 全部 + ktm13 全部） | `封装` / `封装形式`、`供电电压` / `工作电压` | `kth1604sh.md`：`封装 = DFN/FBP 1*1-4L` 与 `封装形式 = DFN/FBP 1*1-4L`；`供电电压 = 1.6 ~ 5.5 V` 与 `工作电压 = 1.6~5.5V` |
| 3（kth25） | 同上 | `kth250xqa.md`：`供电电压 = 2.7 ~ 36 V` / `工作电压 = 2.7~36V` |
| 4（linear-hall） | `供电电压` / `工作电压` | `kth5641*.md` |
| 1（ktm28） | 上述全部 **+** `BOP（Gs）`/`BOP(Gs)`、`BRP（Gs）`/`BRP(Gs)` | `ktm2801-ktm2802.md` 共 14 个字段里 4 个是重复项 |

**建议改法**：两步。① `label_key` 的返回值改成「归一键 → 首次见到的显示名」的映射，即维护 `canon = {}`，`canon.setdefault(k, name)` 后统一 `return canon[k]`——这样 `BOP（Gs）` 与 `BOP(Gs)` 自动并成一个字段。② `label_syn` 补 `'封装形式': '封装'`、`'工作电压': '供电电压'`。归并后两份取值不同的走 P0-3 那条 conflicts 通道。

### P1-2 10 个页面本该有的文档没挂上（`doc_matches` 太紧 / 只在本产品内找）

| 页面 | 漏挂的文档（在 `cache/site.json` 里） | 原因 |
|---|---|---|
| `kth78/kth7101-sop8`、`kth7111-qn16`、`kth7112-qn16` | `KTH7101/7111/7112 产品手册.pdf` | 文档挂在 `products['kth71']` 下，而这三个型号的矩阵行在 `kth78`；`render_model_pages` 只扫 `p['docs']`（行 751） |
| `kth25/kth250xq{a,b,c}` | `KTH2502 产品手册.pdf` + `KTH2502 Datasheet.pdf` | `a='KTH2502'`、`b='KTH250XQA'`，`b.startswith(a)` false、`a.startswith(b[:7]='KTH250X')` false |
| `kth462/kth462{1,2}x-a{m,t}-st6`（4 页） | `KTH462N Series 产品手册.pdf` | `a='KTH462N'`（中文「系列」被 `[^A-Z0-9]` 剥掉后留下 N），`b='KTH4621XAMST6'`，两向都不前缀 |
| `ktm28/ktm2801-ktm2802` | `KTM2802 产品手册.pdf` + `KTM2802 Datasheet.pdf` | `b='KTM2801KTM2802'`，`b.startswith('KTM2802')` false |

（`kth16/kth1731pu` 无文档是真的没有 KTH1731 的资料，属正常。）

**建议改法**：`doc_matches` 的 `a` 侧再多剥一层——`a = re.sub(r'(系列|SERIES|N系列)$','',a).rstrip('X')`；`b` 侧改成只取基础型号 `base_model(mid)` 再比前缀，而不是拿整串订购码；跨产品的那三个走「先在本产品找，找不到再全站按 `base_model` 找一次」。P0-1 拆开 ktm28 后 KTM2802 自然命中。

### P1-3 35 个页面挂上了衍生型号的手册

`doc_matches` 的 `a.startswith(b[:7])` 兜底会让 `KTM1331R`、`KTM1302R`、`KTM1302LTC` 的手册挂到**不带 R/LTC 后缀**的型号页上：

- `KTM1331R Series产品手册.pdf` → `ktm1331{T,M,S}{A..E}` 15 页
- `KTM1302R Series产品手册.pdf` + `KTM1302LTC产品手册.pdf` → `ktm1302{T,S}{A..E}` 10 页（每页各挂 2 份）

这三份文档本身在库里没有对应的型号页（R / LTC 变体不在任何矩阵里），所以不是「挂错就消失」，但当前呈现是「KTM1301MA 的资料里给你一份 KTM1331R 手册」。
**建议改法**：把 `a.startswith(b[:7])` 这条兜底限制成「`a` 去掉后缀字母后与 `b` 的基础型号完全相等」，并在文档表的「型号」列保留 `d['series']` 原文，让读者看得出这是衍生型号的手册；或者干脆给 R/LTC 变体补进矩阵、各自成页。

### P1-4 86 个页面把「类型」当成「等级」

`badge_names = ("等级", "类型")`（行 439）把 `类型` 也认成等级列，`model_lead` 又无条件加「级」字，于是导语写成：

- `ktm13/ktm1301ma.md`：`KTM13 系列 TMR 磁阻开关：**全极型级**、SOT-23-3L / TO-92S 封装、…`（已截图）
- `kth16`：`双脚输出单极型级` / `锁存型级` / `单S极级` / `单N极级`
- `kth462`：`双路输出锁存型级` / `速度和方向双路输出级`

分布：ktm13 59 页、kth16 23 页、kth462 4 页。同一处还污染了小节导语——「与**全极型级**其他型号的差异。」
**建议改法**：`model_lead` 的 `f'{grade}级'` 改成只在等级词表内才加后缀，例如 `grade + ('级' if grade in ('车规','工业','消费') else '')`；小节导语同理（行 780 `grade + "级"`）。更彻底的做法是 `merged_matrix` 分别返回 `grade_col` 与 `type_col`，`类型` 不再当等级徽标用。

### P1-5 specs.json 里 27 行矩阵数据没有任何页面承载

「每张矩阵表的每一行都有且仅有一页」这条不成立——次级矩阵表的行被 `merged_matrix` 按基础型号折进主表后就没有独立页了：

| 表 | 行数 | 处置 |
|---|---|---|
| `kth78 / 系列参数对比` | 11（KTH7801/7802/7811/7812/7813/7815/7816/7821/7822/7823/7824） | 其中 **KTH7802 / KTH7811 / KTH7821 / KTH7822 四个型号在主表里根本没有对应订购型号，整行数据被丢弃，全站无页** |
| `kth16 / 系列概览` | 8 | 均能折进主表，无独立页（合理） |
| `kth16 / KTH1362 型号选型表` | 2（KTH1362TA / KTH1362SA） | **KTH1362 不在主表里 → 这 2 个型号全站无页**，而 `cache/site.json` 里有 `KTH1362` 的手册 |
| `ktm13 / 系列概览` | 6 | 均能折进主表（合理） |

**建议改法**：`merged_matrix` 在合并完之后，把次级表里 `base` 未命中任何 `recs` 的行**追加**成新的 `recs` 条目（字段按该表列填，缺的留 `—`），而不是 `if not targets: continue`（行 464）。这样 KTH7802/7811/7821/7822 与 KTH1362TA/SA 共 6 页会补出来。

## P2（措辞 / 打磨）

### P2-1 导语里「输出接口」重复成词
`model_lead` 拼成 `f'{fields[n]} {n}'`，于是出现 `开漏输出 输出接口`、`线性模拟输出 输出接口`、`模拟电压输出 输出接口`（kth25 / kth31 / kth460 / linear-hall 共 17 页）。
**改法**：接口一项改成 `f'{v} 输出'`，或当 `v` 已以「输出」结尾时不再补 `输出接口`。

### P2-2 `系列` / `产品名称` 被当成参数排进 `参数详情`
`kth7801-x-n-qn16.md` 的参数第一行是 `系列 = KTH7801（符合 Q100）`，`kth3101.md` 有 `产品名称`，`kth460/kth462` 也有。这是表的分组列不是电气参数，放在参数表首行会挤掉真正的关键项。
**改法**：`render_model_pages` 里给 `field_names` 加一个排除表 `('系列', '产品名称', '产品型号')`，或把 `系列` 提到 kicker 行显示。

### P2-3 一行代表多个封装/多个灵敏度档时，导语与芯片会给出并列值
`kth31/kth3101.md` 导语：`SOT-23 / TO-92S / DFN1616 封装`；linear-hall 的 `灵敏度` 芯片一次给四档（见 P0-1）。P0-1 的行展开做掉之后，封装这一类还需要在导语里截断——建议只取第一个封装并在后面加「等 N 种封装」。

### P2-4 `参数详情` 的小节导语对多料号页读起来是坏的
`kth5641a1-….md`：`KTH5641A1 KTH5641A2 KTH5641A3 KTH5641A4 的全部参数，取自KTH564 系列规格表。`——换行被压成空格。P0-1 修好后自然消失。另外 `取自{c["model"]}规格表` 中间缺一个空格（`取自KTH564 系列规格表`）。

## 已核查且通过，不必再看的部分

- **数值保真**：124 页 × 全部字段（合计 1,600 余格）逐格比对 `merged_matrix`，零差异；每格再回溯到 specs/figures 源表，要求列名归一化相等且取值逐字相同，**零条无源、零条单位丢失**（`mA`/`μA`/`nA`、`Gs`/`mT`、`℃`、`bit`、`rpm`、`Hz` 全部随值保留）。
- **覆盖与去重**：`merged_matrix` 产出 124 行 → 124 条唯一路由 → 磁盘 124 个文件，`model_slug` 无碰撞。
- **链接**：型号页里全部 `/msite/...` 链接（面包屑 5 段、同系列对比表头链、所属产品系列 4 张卡、文档下载 `files/*`、CTA）逐个做文件系统存在性校验，**0 断链**；反向检查 10 个系列页的对比表，124 个型号页**全部被链到**。
- **结构一致性**：124 页骨架完全一致（frontmatter → 面包屑 → kicker → H1 → lead → 4 个 c-spec 芯片 → c-actions → 参数详情 → 同系列对比 → 技术文档 → 所属产品系列 → CTA）。缺段的 12 页都是数据决定的（11 页无匹配文档、ktm28 1 页无同系列同伴），不是模板漏渲染。
